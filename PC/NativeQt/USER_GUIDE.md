# 机器人关节伺服驱动与安全控制平台使用说明书

软件版本：1.0.0；技术实现：C++17、Qt Widgets、QSerialPort、QCustomPlot。配套控制板：STM32F407 C板，当前协议固件自报1.1.1，C620 ID1 / CAN1。

## 1. 用途与当前能力

本软件用于连接真实平台、配置有限步骤测试、观察反馈与停止过程、保存原始记录并复核结果。日常操作不需要Keil Debug或Watch；Keil仅用于固件构建、下载和板级排障。

当前可以配置只读反馈、未授权拒绝、受限电流动作和到期停止计划；支持独立停止、条件故障复位、反馈曲线、历史回放和报告导出。原始核对与执行结果分别显示。

当前限制必须与实验结论一起保留：

- 命令值是C620电流命令raw，不是rpm、安培、转矩或机械角度。当前没有目标速度/位置闭环，不能用填写raw替代速度或位置设定。
- 受限电流模式：命令范围−1000…+1000 raw，期限1…100 ms；固定动作模式：仅+1000 raw、1000 ms。能力文件和MCU均参与限制，修改能力文件不能扩大MCU权限。
- 零输出任务类型保留，但当前MCU也要求任务许可，操作会话协议又不发零任务许可。因此普通未许可状态下会在发送前拒绝，不能把这条路径当成已通过的零输出执行实验；软件不会为此申请非零许可。
- 失效或缺失样本不补成0；协议未提供转矩，显示“— Nm”。编码器为0…8191 raw，不能直接当作输出轴机械角度。
- 本次发布已完成主机和离线部署验证。当前C++程序的真实设备通信与运动回归仍需在现场完成；源代码、编译、内存端点结果与现场结果分开记录。

## 2. 安装、启动与文件

完整解压发布ZIP，进入发布目录，双击`MotorTestPlatformNative.exe`。不要只复制EXE；同目录DLL、platforms、profiles和docs均需保留。运行不需要Qt SDK、Python或虚拟环境。

启动默认未连接，不自动建立操作会话、不申请任务许可、不运行电机。关闭再打开软件也不会恢复上次动作。

| 文件或目录 | 用途 |
| --- | --- |
| MotorTestPlatformNative.exe | 软件入口 |
| profiles/c620_m3508_lab_v1.json | 当前设备能力与控制模式描述 |
| plans/readonly_unarmed.json | 前反馈 → 未授权拒绝 → 后反馈，不申请运动许可 |
| plans/single_deadline.json | 前反馈 → 固定+1000raw/1000ms → 后反馈；需本次现场确认 |
| docs/USER_GUIDE.md | 本说明书；软件中按F1可打开 |
| examples/real-feedback.jsonl | 已有真实历史记录，用于离线回放；不是当前实时反馈 |
| source/ | 同版本C++源代码、构建说明及测试；不参与应用运行 |
| release-manifest.json | 发布文件SHA-256与验证范围 |

原始记录默认位于Windows本地应用数据下：`%LOCALAPPDATA%/MotorTestPlatform/NativeQt/sessions`。每次物理连接新建独立JSONL；具体路径可在“设备维护 → 串口工具”查看和复制。测试计划在同一连接日志内以独立run_id保存。

记录只追加；另存草案、导出CSV/JSON均要求新文件名，已存在文件拒绝覆盖。文件SHA定位的是文件快照，开放日志继续追加后SHA会变化。

## 4. 连接真实平台与MCU状态

连接前按当前现场条件核对供电、共地、CANH/CANL、终端、限流、机械固定、急停和快速断电。接线或功率状态有变化时重新核对；不要用危险堵转确认保护。

1. 右上连接用途选择“平台任务与监测”。
2. 选择实际CH340端口（COM号可能变化），波特率115200；本软件串口格式固定8N1、无流控。
3. 点击“连接”。软件只自动读取设备信息和MCU状态，不建立操作会话。
4. 查看顶部状态。空闲时对已正常回复的状态约500ms更新一次；采集中由采集器约每10次轮询读取状态；计划执行中由执行器协调通信。
5. 查询超时后不自动重试，物理串口正常时保持连接；状态过期显示“当前许可未知”。排查设备后点击“刷新状态”，成功回复后恢复空闲状态更新。

“串口已连接”仅证明PC端口打开；“MCU ONLINE”证明匹配状态回帧中的Safety状态；“输出许可1”也不是机械运动或停稳证明。状态超过1000ms即为历史快照。设备UID/固件是本次匹配自报，未做密码学认证或全Flash读回。

| 状态 | 含义与操作 |
| --- | --- |
| INIT | MCU初始化中；等待状态稳定 |
| WAIT_FEEDBACK | 等待有效电调反馈；先检查功率、物理层与CAN |
| ONLINE | 已在线；输出许可仍需单独判断 |
| ACTIVE | MCU存在活动动作；通过独立停止处理 |
| SAFE / FAULT | 查看故障码，消除现场原因后才申请条件复位 |
| 快照过期/连接断开 | 当前许可未知；不能沿用上次ONLINE作为启动依据 |

## 5. 反馈与曲线

在“设备监测”点击“开始采集”。设备必须声明反馈查询能力；每100ms发一次只读轮询，不写入运动许可。

转速、电流、编码器和温度各有独立纵轴，横轴为MCU样本相对时间（秒）。曲线颜色与通道名称对应；右上图内标签显示该通道最新样本，点击曲线显示所选历史点的图内读数和MCU tick。

- 勾选通道决定曲线可见性，不改变MCU采集或日志。
- 时间窗可选1/5/10/30/60秒。
- 滚轮缩放，拖动查看；手动操作后停止跟随。
- “回到最新 / 自动缩放”或双击恢复跟随和自动纵轴。
- 点击“停止采集”只停止只读轮询，不等同于停止电机；历史曲线保留。
- 实时图保留最近6000点；完整收到的原始字节仍写入JSONL。反馈过期500ms时数值区不再作为实时值使用。

图中停留的曲线、游标读数与当前实时反馈是不同含义。失效点和超过1秒的样本间隔会断线显示。

## 6. 配置与保存测试计划

“测试任务 → 配置计划”默认是一条只读反馈步骤。可载入发布包的计划，也可添加/删除步骤、修改字段。

| 字段 | 约束 |
| --- | --- |
| 计划ID、步骤ID | 小写字母开头，后接小写字母/数字/下划线，3…64字符；步骤ID不能重复 |
| 目的 | 1…200字符，前后无空白 |
| 测试类型 | 只读反馈、零输出、未授权拒绝、受限动作、到期停止 |
| 控制模式 | 受限电流≤100ms或固定+1000raw/1000ms |
| 命令raw | 只读反馈无命令；零输出/未授权拒绝必须0；运动值受能力和MCU共同约束 |
| 期限ms | 只读反馈0；其他按控制模式限制 |
| 轮次 | 每步骤1…16；最多16步骤，总展开轮次最多32（每轮预留2条记录，最多64） |

点击“校验计划”检查结构、能力文件原始SHA、参数、轮次与记录预留。草案有效仅说明可形成冻结输入，不代表已授权执行或现场条件满足。

“另存草案”保存可再次载入的JSON。**载入草案只能选择测试草案**，不能选择会话报告、核对报告或能力文件；选错时会拒绝，不会把报告转换成任务。

启动时复制本次草案和能力原始字节，计算SHA，之后编辑表格不会更改已运行的快照。改能力文件会改变SHA，需要重新生成与该文件匹配的草案。

## 7. 执行与独立停止

先完成当前现场核对；非零动作必须得到本轮实验明确同意，再执行对应计划。下列软件步骤说明不会自动替代现场确认。

### 7.1 只读与未授权拒绝

载入`plans/readonly_unarmed.json`，保持没有操作会话/许可，不勾选运动确认；进入“执行与结果”点击“启动计划”。

预期三行依次为新鲜反馈、预期安全拒绝、新鲜反馈。中间拒绝是该实验的通过条件，不能解释为任务执行成功。反馈中断时不会继续把后续步骤当成通过。

### 7.2 一次受约束动作

载入`plans/single_deadline.json`，核对+1000 raw、1000ms、1轮及当前现场条件。先点击顶部“建立操作会话”，然后勾选本次运动确认并明确点击“启动计划”。确认勾选启动后清空，下次需要重新确认。

软件先核对设备能力、MCU状态和剩余记录容量；逐动作申请与完整任务参数绑定的一次性许可，再发送唯一任务。许可未使用10秒失效；保活周期250ms，MCU会话失联1000ms撤销许可并请求停止。参数与安全时限不由界面自由扩大。

等待同请求停止回执期间，软件继续独立保活并查询反馈。到期停止必须原因1、故障0、实际MCU时间达到期限，不能把主动停止/失联停止算作到期通过。

### 7.3 三个停止/断开入口的差别

| 操作 | 实际作用 |
| --- | --- |
| 停止后续排程 | 取消尚未发送的后续步骤；已发送任务仍等待回执/超时，不保证当前动作立即停止 |
| 顶部“停止 / 撤销许可” | 向MCU发送独立停止请求，并取消后续排程；收到操作OK不代表机械已停稳 |
| 断开 | 用户主动关闭物理串口；停止保活，不能代替现场急停或快速断电 |

主动停止到期计划时，该步骤会显示提前停止/失败，计划中止；这是到期判据的正确结果，不能改判“到期通过”。需要结合匹配原因4停止回执和实际电机表现验证主动停止。

正常结束、取消或回执超时后，软件尝试一次关闭操作会话并读取最终状态，确认许可0、活动任务0、要求零输出1；**正常物理连接保持，不需要每次重新连接**。未知/迟到结果不重发动作，也不反改已终结计划。真实串口错误、日志写入失败或64MiB上限会关闭连接。

## 8. 故障恢复

按供电/参考地 → 启动/时钟 → 物理层/接线 → 外设 → 协议 → 调度 → 应用安全的顺序排查。不要反复点击复位掩盖故障原因。

E003曾用于CAN反馈丢失路径。电调恢复供电或反馈恢复不等于自动清除锁存故障。需要建立操作会话后申请条件故障复位；MCU只有在恢复条件满足时才接受，拒绝时故障保留。成功后仍应ONLINE、许可0、活动0，不自动运行。

故障实验中先保留原始记录、截图和实际现象，记录最后正确点、首个错误点和操作顺序。运动中异常实验不能用静止断电实验替代。

## 9. 历史回放、导出与严格核对

“记录回放 → 打开实验记录”选择JSONL。软件从原始TX/RX匹配请求和nonce，解码样本；显示原文件SHA、有效/未关联/损坏帧数量。历史数据不会变成当前MCU状态。

播放/暂停、上一点/下一点、进度条和2/10/20点每秒仅控制回放。末尾自动停止，再播放从头开始。图内游标、各通道纵轴和时间窗与实时页一致。

| 导出入口 | 内容 |
| --- | --- |
| 导出反馈CSV | 关联样本：请求、MCU/末次接收tick、编码器raw、rpm、电流raw、温度、新鲜标记、源SHA |
| 导出核对摘要 | 历史解析计数和文件信息；不是完整计划的独立核对报告 |
| 测试任务/导出执行结果 | 当时执行状态与各步骤结果，标明在线状态观察范围 |
| 测试任务/核对本次原始记录或核对历史记录 | 从当前格式原始字节、实际排队写入、冻结快照和单调时间独立重算 |
| 导出核对报告 | 核对结果、执行结果、来源SHA、各请求、停止和最终状态证明 |

载入较大历史或进行严格核对前，需结束任务并关闭操作会话，以免文件处理影响保活。保持普通串口连接即可，不要求为归档断开。

| evidence | 解释 |
| --- | --- |
| complete | 文件快照中的必要记录完整且重算一致；计划本身仍可能失败或中止 |
| partial | 缺失回执、结束或最终状态等证据 |
| invalid | 数据格式、时间、原始证明或摘要与重算不一致 |
| not_applicable | 文件不含测试计划 |
| unsupported_format | 缺少该重算器所需输入，不能视作通过 |

MCU状态不是机械停稳测量。要确认停稳需用户观察或外部测量；日志自洽、设备自报、原文件SHA均不能替代这一点。

## 10. 串口维护工具

先断开当前连接，将右上用途切换为“通用串口维护”，选择端口和波特率后连接。用途在连接期间锁定。维护模式不发状态/设备查询，不建立操作会话、不执行计划，也不把收到的二进制误判成当前MCU状态。

维护工具会发送你输入的实际字节。连接真实平台时仅输入已核对且符合本轮实验授权的内容；不要用手工帧绕过计划参数和现场确认。

| 格式 | 输入示例与规则 |
| --- | --- |
| 文本 | UTF-8支持中文；Latin-1仅允许可表示的0…255字符，不能表示时拒绝 |
| HEX | `01 0A FF`或`010AFF`；每字节两位，不用0x、逗号、符号 |
| DEC | `1 10 255`，空白分隔，各字节0…255 |
| BIN | `00000001 00001010 11111111`，空白分隔，每个数≤255 |
| OCT | `001 012 377`，空白分隔，每个数≤255 |

结束符可选无/LF/CR/CRLF，按字节追加。预览显示总字节数和前64字节HEX；单次上限4096字节（含结束符）。非法字符、奇数HEX、超量程、无法编码和超长输入会禁用发送。

点击“发送一次”只排队一次，不循环、不自动重发。收发显示可切换进制/编码，计数为原始字节数；显示只保留最近16KiB并合并刷新，原始日志持续追加。“清空显示”只清界面缓冲与计数，不删除日志、协议状态或设备数据。

固定8N1/无流控；本版本不提供其他数据位/奇偶校验/停止位。输入超过有界缓冲、写入不完整或真实串口错误时关闭连接，不自动恢复发送。切回平台用途需明确断开、切换、重新连接。

## 11. 自行检查功能的简表

先用发布包历史记录进行离线检查，无需重复电机实验。涉及连接或运动的检查由现场条件与本轮授权决定。

| 检查 | 合格表现 |
| --- | --- |
| 启动/F1/缩放 | 未连接、无任务自动开始；说明书可读；小窗口可滚动访问底部 |
| 历史载入 | 真实样本数量和源SHA显示，MCU当前状态仍未知 |
| 播放/暂停/步进/首尾/速度 | 编号与曲线跟随；暂停保持；速度变化可见；末尾停止 |
| 图形交互 | 通道显隐、独立纵轴、缩放拖动、回到最新、点击读数一致 |
| CSV/摘要 | 新文件成功；同名拒绝；源SHA能对应JSONL |
| 草案编辑 | 恢复后载入一致；命令/期限越界、重复ID、错误文件被拒绝 |
| 用途隔离 | 平台连接禁手工发送；维护连接不发平台查询/授权；在线不能换用途 |
| 接收/发送 | 已授权的字节与预览一致；显示转换不改变原始记录；清显示不删除记录 |
| 正常计划 | 每步骤按实际回执判断，测试后串口保持；不自动重复动作 |
| 原始核对 | complete与任务通过分开；缺必要数据不能通过；已有报告不能覆盖 |

## 12. 常见问题与边界

- **端口打不开**：先关闭占用同COM的串口软件/其他进程；刷新端口检查实际COM。不要同时用两个程序控制同一平台。
- **连接但无状态**：核对115200/8N1、串口接线、MCU启动和匹配协议；设备供电与串口打开是两件事。
- **ONLINE但不能启动**：查看许可、故障、活动任务、记录剩余和会话；未许可拒绝是正常边界，不直接强写arm。
- **已收到字节但没有曲线**：先确认是平台用途、支持反馈能力、请求关联及新鲜样本；不要把杂字节当成有效反馈。
- **停止后步骤显示失败**：到期判据遇到主动/故障/失联停止本来就不通过；查停止原因和实际现场表现。
- **未执行第三步**：前一步失败、中止或不确定时，不继续排后续步骤。
- **测试结束提示状态未知**：刷新匹配状态，确认许可0/活动0；不要直接重跑未知动作。
- **载入JSON报错**：区分草案、能力文件、执行报告、核对报告。错误文件不会自动转换。
- **日志写满**：64MiB上限后停止本连接，不追加超界数据；保留文件，以新连接建立新日志，不覆盖原始证据。
- **运行依赖错误**：重新完整解压，检查platforms及Qt/MinGW DLL；不要从构建目录单独拷贝EXE。

## 13. 离线命令行与复现

仅离线核对，不打开串口：

```powershell
.\MotorTestPlatformNative.exe --audit-log "原始记录.jsonl" --report "新核对报告.json"
.\MotorTestPlatformNative.exe --replay ".\examples\real-feedback.jsonl"
```

离线核对退出码：0=complete；2=partial/不适用/格式不支持；3=invalid；4=参数或报告写入失败。同名报告不覆盖。

完整C++源代码和测试见source/PC/NativeQt，构建环境/参数见其中README.md与build.ps1。主机测试使用内存端点，不连接真实串口；部署自检用已有历史文件，报告必须保留`serial_opened=false`。
